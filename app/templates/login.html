why this is the weak part of the design
A partner application holding KVARK passwords is not the shape a real integration should ship. The gateway already carries the better path — it accepts a directory-issued token when AGENT_GATEWAY_IDP_ISSUER, _AUDIENCE and _JWKS_URL are configured against the same Microsoft AD the accounts came from. Nothing else in this application changes when that lands: everything downstream already treats the token as opaque.
